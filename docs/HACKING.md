## Commit messages

The commit message should be structured as follows:

<type>[optional scope]: <description>

[optional body]

[optional footer]

The commit contains the following structural elements, to communicate intent to the consumers of your library:

- fix: a commit of the type fix patches a bug in your codebase (this correlates with PATCH in semantic versioning).
- feat: a commit of the type feat introduces a new feature to the codebase (this correlates with MINOR in semantic versioning).
- BREAKING CHANGE: a commit that has the text BREAKING CHANGE: at the beginning of its optional body or footer section introduces a breaking API change (correlating with MAJOR in semantic versioning). A breaking change can be part of commits of any type. e.g., a fix:, feat: & chore: types would all be valid, in addition to any other type.

DO NOT include `Generated with Claude Code` or `Co-authored-by: Claude`.
You should include `Assisted-by: Claude <noreply@anthropic.com>` though
especially for nontrivial changes that did not require substantial assistance from
a human.

### Rollout handoff

The prerequisite is a reviewed immutable shared wrapper implementing explicit,
off-by-default draft admission and the independent result writer specified by
[agent-board's draft result contract](https://github.com/cgwalters-forge/agent-board/blob/main/docs/poll.md#draft-review-result-contract)
(agent-board#680). The exact bcvk dispatch workflow is currently **absent**;
central rollout must not point `reviewWorkflow` at `review.lock.yml`. A future
base-owned caller must use `kind=review`, bind the expected current head, and
read the fixed task and bounds from its trusted default-branch checkout, never
from dispatch-selected paths or head files. `workflow/review.md` and
`workflow/review.toml` are the inspected wrapper's fixed task/bounds paths, not
files shipped in bcvk today. Its optional command admission also reads
`workflow/review-command.toml`; this does not authorize a draft route.

The required result is one Actions-bot `APPROVED` review at the inspected head,
with exactly one `agent-board-draft-review` JSON fence of schema
`agent-board/draft-review/v1` and the single gh-aw run marker. It must bind
repository, PR, reviewed head and exact current title/description, and contain
actual semantic diff and description assessments, category, risk, concrete
evidence and reason. Unknown evidence stays deep. CI needs a complete nonempty
current-head inventory, successful rollup and no failed, pending or missing
required checks; do not treat an unavailable CI read as success.

Provenance must identify the successful completed configured default-branch
dispatch run, its latest attempt and preceding bot-authored head reservation.
Exactly one successful completed job named `agent-board-review-result-v1`
must belong to that run and contain the review submission time within its
start/end interval (one page, at most 100 jobs; partial reads stay deep).
Only the independent checked writer may own that name, conditional on
`kind=review`. The head is data inside a token-free sandbox; the writer must
never execute it or consume unchecked agent output. Evidence and reason each
have a 1024-byte single-line limit; the whole result body is at most 8192 bytes.

Before installation, shared offline fixtures must reject default-disabled or
unauthorized draft admission, stale heads at admission and publication, wrong
repository/PR/base, changed title/description, unchecked output, and forged,
missing, duplicate or wrong-attempt result-job provenance. These fixtures have
not been added or run here: there is no compatible writer to exercise. Keep
existing ordinary review, rescue and central `pr.noMerge` guards; this route
grants no ready, fix, promotion or merge authority. Central polling remains off.
Before any opt-in, establish one owner for automatic reviews to avoid a second
dispatch for the same head, and record the actual caller filename and approved
wrapper SHA. Preserve gh-aw source/lock conventions: edit workflow Markdown and
regenerate locks with `gh aw compile`, never hand-edit generated lock jobs.
