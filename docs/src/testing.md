## Prerequisites

Integration tests require KVM/QEMU and podman. For libvirt tests, ensure libvirtd is running and your user has libvirt group membership.

## Running Tests

```bash
# Unit tests
just test
cargo test --lib

# Integration tests (requires KVM, podman)
just test-integration
cargo test --test integration

# Specific test with output
cargo test test_name -- --nocapture
```

## Unit Tests

Place tests in `#[cfg(test)] mod tests` blocks within source files. Use nested modules to organize related tests.

## Integration Tests

Integration tests in `tests/` require network access to pull bootc images, working virtualization, and disk space. VMs need time to boot - account for this in test timeouts.

```bash
# Pull test images first
podman pull quay.io/fedora/fedora-bootc:42
```

## Manual Testing

```bash
# Ephemeral VM
bcvk ephemeral run -d --rm --name test quay.io/fedora/fedora-bootc:42
podman stop test

# SSH access
bcvk ephemeral run -d -K --name ssh-test quay.io/fedora/fedora-bootc:42
bcvk ephemeral ssh ssh-test "hostname"
podman stop ssh-test

# Disk image
bcvk to-disk quay.io/fedora/fedora-bootc:42 /tmp/test.img

# libvirt
bcvk libvirt run --name test quay.io/fedora/fedora-bootc:42
bcvk libvirt ssh test "uptime"
bcvk libvirt rm test
```

## Cleanup

```bash
# Remove test containers
podman ps -a | grep test | awk '{print $1}' | xargs -r podman rm -f

# Remove test disk images
rm -f /tmp/test-*.img

# Remove libvirt test VMs
virsh list --all | grep test | awk '{print $2}' | xargs -r virsh destroy
virsh list --all | grep test | awk '{print $2}' | xargs -r virsh undefine
```

# Run test with full output
cargo test test_name -- --nocapture --test-threads=1

# Debug logging
RUST_LOG=debug cargo test test_name

# Check KVM access
ls -la /dev/kvm

# Check VM is running
podman ps | grep test-vm

### Failed `to-disk` installs

On a failed install (including base-disk creation for `libvirt run`), bcvk
collects guest `dmesg` over SSH and both root-filesystem and host-storage
virtiofsd logs **before** removing the container. Each capture has a 30-second
timeout; diagnostics can add up to roughly 90 seconds before cleanup. Failed
captures are noted alongside available logs, without replacing the original
install error or preventing container/disk cleanup. Each captured stream is
capped at 4 MiB to avoid exhausting host memory during failure reporting;
oversized captures are marked truncated. Bytes received before a timeout or
nonzero exit are retained and marked incomplete. Successful installs do not
collect diagnostics. This is evidence collection, not an ESTALE fix.

Logs are saved in a private `bcvk-to-disk-failure-*.log` file in the host's
temporary directory (`TMPDIR` if set). The file is kept after container removal;
stderr normally shows only its path. Copy it to CI artifacts or elsewhere before
the host's temporary-file cleanup runs, then remove it when no longer needed.
If every capture is unavailable, no file is created and reasons are debug-logged.
For varlink installs, notices go to the **server's stderr**, not the client.

To include tails in stderr/test reports, set `BCVK_PRINT_FAILURE_LOGS=1` or enable
debug tracing (`RUST_LOG=debug`). Tails are off by default to avoid flooding normal
error output; each log is limited to its last 200 lines and 32 KiB. A save failure
also prints these bounded tails. The integration harness sets the variable on its
command environment and retains captured stdout/stderr when a to-disk command
exits nonzero. Saved files contain logs up to the capture limit, which may include sensitive
guest data; review them before sharing.

#### Deferred VM verification

Only run this with working `/dev/kvm`, QEMU/virtiofsd and podman, sufficient disk
space, and a locally pulled bootc image. Build with `just build`, then use a fresh
directory so no cached disk can mask the result:

```bash
work=$(mktemp -d)
image=quay.io/centos-bootc/centos-bootc:stream10
target/release/bcvk to-disk --filesystem ext4 --disk-size 2G --label bcvk.failure-check=1 "$image" "$work/fail.img" >"$work/stdout" 2>"$work/stderr"
rc=$?
test "$rc" -ne 0
```

Run without shell `errexit` for that expected failure. Verify stderr still contains
the original bootc/install error and the saved-log path, but no log blocks by
default. Confirm `fail.img` is absent and
`podman ps -a --filter label=bcvk.failure-check=1` lists no container. Open the
announced file **after** cleanup and verify guest dmesg and both virtiofsd sections
(an empty virtiofsd log is valid). Keep that file as an artifact. If the chosen
image fits in 2G, reduce the disk size until installation, not host validation,
fails. Repeat with `BCVK_PRINT_FAILURE_LOGS=1` and check bounded tails; repeat with
`RUST_LOG=debug` to exercise debug tracing. Finally run:

```bash
target/release/bcvk to-disk --filesystem ext4 --label bcvk.failure-check=1 "$image" "$work/success.img"
BCVK_PATH="$PWD/target/release/bcvk" BCVK_PRIMARY_IMAGE="$image" cargo test -p integration-tests -- test_to_disk --exact
```

Both normal installs must succeed without failure-log notices. Also repeat an
expected failure through a temporary integration test using `output_or_bail`,
and verify its error/report retains the original error, path and tails. Do not
count compile-only or unit tests as runtime verification of VM cleanup.
